# PDF互動講義批改系統

把教師的 PDF 講義變成可分版管理的線上互動教材。一個版面可加入多份 PDF 教材，各教材的問答區、筆跡、課堂狀態、作答與草稿彼此隔離。學生以暱稱進入，針對教師放置的問答圖釘輸入文字或拍照上傳；教師可在平板上以觸控筆直接閱讀 PDF、書寫、標記圖釘、查看答案與批改。

## 檔案

- `index.html`：原生 HTML、Vanilla CSS 與 Vanilla JavaScript 前端。
- `Code.gs`：Google Apps Script API，使用 Google 試算表保存索引，使用 Google Drive 保存 PDF、照片與大型 JSON。
- `rdq/`：已確認的 RDQ 需求規格卡。
- `assets/`、`css/`、`js/`：預留的靜態資源資料夾；目前前端維持單檔，方便 GitHub Pages 或本機開啟。

## 使用方式

### 本機示範

直接開啟 `index.html`，在連線設定視窗選擇「本機示範模式」。本機模式的 PDF、照片、版面與批改資料只保存在目前瀏覽器，適合先測試操作流程，不代表跨裝置同步已完成。

### GAS 部署

1. 建立一份新的 Google 試算表。
2. 選擇「擴充功能」與「Apps Script」，將 `Code.gs` 全文貼上並儲存。
3. 在 Apps Script 編輯器執行 `initDatabase` 一次，完成資料表與 Drive 權限初始化。
4. 選擇「部署」、「新增部署」、「網頁應用程式」。
5. 執行身分選「我自己」，誰可以存取選「任何人」，完成部署。
6. 前端已將 GAS Web App 網址寫死在 `index.html` 的 `DEFAULT_GAS_URL`；若日後重新部署 GAS，再替換該常數即可。
7. 首次使用時，GAS 會自動建立「系統設定」、「教材版面」、「問答區」、「教師手寫」、「課堂狀態」、「作答紀錄」與「檔案索引」工作表，以及 Drive 根資料夾。
8. `Code.gs` 更新後，請在「部署」中建立新版本；快取與背景佇列才會套用到 Web App。

## 資料設計

- 「教材版面」保存每一版的名稱、說明與版面層級索引；「課堂教材」保存同一版面下每份 PDF 的名稱、說明、排序與 Drive 檔案索引。
- 「問答區」保存 `materialId` 及相對於 PDF 頁面的圖釘百分比座標，因此不同教材不會互相顯示，縮放後仍能對準原位置。
- 「教師手寫」與「課堂狀態」保存 `materialId`，教師切換教材時只讀取目前教材的頁面與筆跡；學生端約每 3 秒跟隨教師的教材、頁碼與縮放。
- 「作答紀錄」與學生草稿保存 `materialId`，作答 ID 也依教材隔離；內容包含暱稱、文字答案、照片檔案索引、教師批改狀態與評語。
- 「檔案索引」保存 Drive 檔案 ID 與 `materialId`。照片、PDF 與大型 JSON 不直接塞進試算表儲存格。
- 教師可從版面卡片或編輯頁永久刪除版面；刪除時會一併清理 PDF、問答區、學生作答、照片、教師批改、手寫筆跡、JSON 附件、Drive 版面資料夾與本機快取。
- 所有新增、修改、封存、刪除教材、刪除版面、作答與批改都先寫入瀏覽器 IndexedDB，再依序放入 outbox 背景傳送；傳送失敗會保留佇列，不用遠端回應覆蓋較新的本機內容。
- 教師筆跡以相對座標 JSON 保存，課堂輪詢只在版本變更時讀取 Drive；已讀過的 PDF 與照片也會以檔案 ID 快取在本機。
- 試算表資料會短暫快取 8 秒，因此直接手動修改工作表後，最多可能延遲 8 秒反映。

## 第一版邊界

- 主要目標為單班約 30 人的課堂使用。
- 教師端支援手寫筆、螢光筆、圖形、橡皮擦、本頁清除與全部清除；系統依輸入來源分流，觸控筆或滑鼠直接書寫，手指可用來滑動並捏合縮放 PDF。
- 課堂與批改區預設筆畫粗細為 2，可再選擇 4、6、8；橡皮擦請由工具列或鍵盤 `E` 切換，避免提筆再落筆被誤判為雙擊。
- 學生不使用畫筆，學生答案以文字與壓縮照片為主。
- GAS 版採定時同步，不做多人同一畫布的即時共同書寫。
- 教師課堂 PDF 的頁碼與手寫標記採落筆後批次同步，學生端約每 3 秒更新一次。
- 不納入 Firebase、Google 帳號登入、AI 評分、語音回答與正式版本歷史。
- 學生照片預設在瀏覽器端壓縮至寬度 800px，並限制每題張數與大小。

## 注意事項

學生只填暱稱時，身分辨識屬於課堂活動等級，不是正式帳號系統。若日後要長期保存成績、跨班管理或公開提供服務，應追加真正的權限驗證、資料保留政策與更嚴格的檔案存取規則。
